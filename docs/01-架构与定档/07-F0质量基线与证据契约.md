# F0：质量基线、历史类型债务与证据契约

> 状态：**F0 已完成并通过统一验收**（2026-09-09）。代码候选为 `87ff1988a29239468624473e56640b507e79bb4d`，脱敏结果索引见 [F0 quality evidence manifest](../../artifacts/acceptance/f0/2026-09-09-f0-quality-baseline.evidence.json)。该通过只建立质量和证据基线，不将任何账户变更为 `READY`，也不替代 F1--F6 的专项验收。

## 1. 目标与非目标

F0 只收口当前 TradeCore 源码的质量和可追溯性基础，不改变 EMT 副作用、Journal 格式、账户 gate 或 C0--C7 热路径。它完成以下四项：

1. 默认 Pyright 严格范围归零，且不以 `# type: ignore`、放宽配置或跳过目录规避错误。
2. 将旧 P0 `emt_gateway` 与 `tools/` 的类型债务显式分层，防止“未纳入默认严格检查”被误读为无债务或已验收。
3. 将 Redis 设计的历史性与 `MmapJournalProfileV1` 的现行性写明，避免旧部署文字重新成为运行依赖。
4. 固定每一个 F 包共用的、无敏感载荷的 evidence manifest JSON Schema 和敏感信息扫描门禁。

F0 不实现 `MergeManifestV2`、恢复 reader、真实 EMT adapter 副作用、PostgreSQL projector、PaperBroker/QMT profile 或任何性能优化；这些分别属于 F1--F6。所有账户继续 `DISARMED`。

## 2. 当前默认质量门禁

默认严格 Pyright 范围固定为 `xuanling_tradecore/` 与 `emt_gateway/operational_telemetry.py`，定义于 `pyproject.toml`。此范围是当前产品核心、运行时状态、Adapter 边界和受限 telemetry seam 的最低质量基线，必须保持零错误。

F0 新增以下不能进入热路径的控制项：

- `tools/quality/check_sensitive_content.py`：扫描 Git 跟踪文件与非忽略的新文件；仅输出规则号、路径和行号，绝不回显命中的值。
- `contracts/evidence/v1/schemas/functional-package-evidence-manifest-v1.schema.json`：所有 F 包统一使用的 payload-free 证据索引契约。
- `contracts/evidence/v1/examples/functional-package-evidence-manifest.example.json`：可验证示例，不能替代真实验收证据。

敏感扫描是防误提交门禁，不宣称可检测所有泄露形式。账号、密码、私钥、令牌、原始订单、原始回包、主机地址与未脱敏 trace 一律不进入 Git；原始受限证据留在受控运行环境。

## 3. 历史 P0 与工具类型债务账本

2026-09-09 使用 `python -m pyright emt_gateway tools --level error` 的治理快照为 **114 errors**。该命令是债务盘点，不是当前默认 Pyright 的替代门禁，也不得被用作 F0 通过条件。后续修复必须在对应目录的功能包内完成，并以专用、零错误的范围命令闭合。

| 范围 | 当前归属 | 可否出现在 C0--C7 | 类型债务处理方式 | 退出要求 |
| --- | --- | --- | --- | --- |
| `emt_gateway/`（除 `operational_telemetry.py`） | P0 兼容实现、旧 SDK/session bridge、受控测试支撑；核心层只能经 `xuanling_tradecore.compatibility` 访问。 | 不作为新的 TradeCore 核心层依赖；已存在的受控 EMT composition 仅可在 F2 的真实副作用组合中单独审计。 | 保持默认严格范围外；禁止新增无类型 SDK 漏洞或用 `ignore` 隐藏错误。按模块建立专用 Pyright 目标。 | F2 前为实际调用的 compatibility seam 建立零错误命令；未接入的遗留模块继续标记 compatibility-only。 |
| `tools/performance/` | 受控验收、只读 probe、性能 driver 与报告生成；由人工/CI 显式调用。 | 否；只能观察或驱动热路径，不能被热路径导入。 | 以每个 driver 的配置/JSON 输入校验和定向测试治理；SDK 动态导入错误不得扩散到核心包。 | F2/F4 前，对实际 EMT 499-burst driver 与报告生成链设置零错误子范围。 |

## 4. Redis 历史记录的现行解释

现行可执行 profile 只有 `MmapJournalProfileV1`。旧实施方案中 Redis Function、Redis Stream、UDS/ACL、AOF/RDB、Redis 恢复与部署文字仅保留为演进审计：它们不是当前部署前置、运行时依赖、热路径等待项或验收条件。

当前规则如下：

- C1→C2 与 C5→C6 以 mmap frame 的最后 commit word 为本机进程崩溃围栏，不等待 Redis、数据库、archive 或网络 I/O。
- Redis 若未来被重新采用，只能作为新 profile 的独立定档；必须有新的 schema、恢复语义、热路径影响分析和完整功能包验收，不能以历史段落或旧代码自动恢复。
- F1 的 `MergeManifestV2`、恢复 reader 与 projector 以 mmap 已验证事实为准；PostgreSQL 和可选 archive 都是可重建的后置消费者。

权威状态以 [当前版本完善与统一验收路线](./06-当前版本完善与统一验收路线.md) 和 [Mmap-EMT 延迟优化实现状态](../04-测试验收与性能/03-EMT接口性能/05-Mmap-EMT延迟优化实现状态.md) 为准。历史主方案相应章节已加历史标识，不能独立引用为现行操作步骤。

## 5. 功能包 evidence manifest 契约

每一个 F 包编码完成后、统一验收开始前冻结候选 commit；完成 A1--A5 后写入一份符合下列 Schema 的证据索引：

`contracts/evidence/v1/schemas/functional-package-evidence-manifest-v1.schema.json`

| 字段 | 用途 | 安全要求 |
| --- | --- | --- |
| `package_id` / `manifest_id` | 精确识别 F0--F6 与单次验收。 | 仅稳定标识，不含账户或操作员。 |
| `candidate_commit_sha` | 绑定被冻结的代码候选。 | 使用 Git SHA，不记录 remote URL。 |
| `environment_hash` / `profile` | 绑定脱敏环境指纹和执行 profile。 | 不包含主机/IP、账户、路径、密码或 SDK 二进制原文。 |
| `test_commands` | 记录每项 A1--A5 命令、退出码与结果。 | 命令不得含凭据、订单参数或连接串。 |
| `result_summary` | 汇总已通过、失败、跳过项及受限结论。 | 不粘贴原始日志或回包。 |
| `known_limitations` | 记录尚未证明的边界，例如 `DISARMED`、manual-only recovery。 | 不把限制缺失伪装成通过。 |
| `evidence_references` | 以仓库相对路径和 SHA-256 引用脱敏证据。 | 只能引用 `docs/`、`artifacts/` 或 `contracts/` 下允许版本化的文件。 |

Schema 验证通过只说明 evidence 的结构完整；不自动将 `acceptance_status=passed` 解释为 `READY`、生产发布或自动恢复资格。

## 6. F0 统一验收步骤

仅在本包所有代码、文档、Schema 和脚本已冻结后按下列顺序执行一次：

1. A1：`ruff check .`、`ruff format --check .`、`python -m pyright`、`git diff --check`、`python tools/quality/check_sensitive_content.py`。
2. A2：`python -m pytest -q`，并验证 evidence Schema 示例与敏感扫描的正/反例测试。
3. A5：确认 `.local-secrets/`、`data/`、`run/`、`logs/`、性能/临时 runtime artifact 均受 `.gitignore` 保护；对本次 Git diff 做人工脱敏复核；所有文档链接可解析。
4. 将结果写入一次真实 F0 evidence manifest。该 manifest 只引用冻结候选 commit 与脱敏结果；若任一门禁失败，写 `failed` 或 `blocked`，不得事后篡改为通过。当前结果为 [2026-09-09 F0 quality evidence manifest](../../artifacts/acceptance/f0/2026-09-09-f0-quality-baseline.evidence.json)。

F0 不要求 EMT 委托、499 burst、Linux 故障演练或 OMS 容量压测；这些测试必须留在改变相应功能的 F1--F6 完整包结束后集中执行。
