# TradeCore 当前版本完善与统一验收路线

> 状态：**现行开发执行路线**。本文件只编排当前版本的代码收口、统一验收和证据产出顺序；不会替代 [OMS / EMS / BrokerAdapter / PaperBroker 模块化实施方案](./04-OMS-EMS-Adapter-PaperBroker模块化实施方案.md) 中的领域边界、副作用不变量或 fail-closed 规则。
>
> 基线：Linux x86_64、项目独立 CPython 3.10 `.venv`、`MmapJournalProfileV1`、EMT-only 默认运行范围。Redis 内容仅保留为历史设计/兼容审计，不能重新成为当前热路径或验收前置条件。
>
> 当前安全结论：所有账户保持 `DISARMED`；不得把代码、单项模拟盘样本、OMS 旁路吞吐或进程在线表述为 `READY`、自动恢复通过或生产可用。

## 1. 目的、适用范围与完成口径

当前仓库已经具备大量领域、执行、Journal、OMS sidecar 和性能平台代码，但仍有“代码存在”“单项定向验证”“完整功能包验收”三种不同状态。本路线把后续工作收束为可交付的功能包，避免在每个小改动后重复执行真实 EMT 压测，或把中间结果误报为完整交付。

### 1.1 当前已知基线

| 能力面 | 当前事实 | 不应外推的结论 |
| --- | --- | --- |
| EMT 热路径 | 三个独立 scope/session/native lane、pre-native 与 callback mmap Journal、499 笔模拟盘 burst 已有基线。 | 模拟盘 F2/F4 已证明受控副作用与旁路非干扰；不代表自动恢复或生产 SLA。 |
| OMS 旁路 | facts、projector、immutable snapshot、watermark/health 及 W0--W6 已完成；已有持续 `2,000 TPS` ingest 与 `9,500 QPS` snapshot 查询证据。 | 不代表 OMS 可同步授权柜台副作用，也不替代 W7。 |
| 恢复与控制 | control root、ownership fence、recovery/reconciliation 纯函数、人工控制面与 manual-only EMT 证据链已存在。 | `RecoveryAutoResolutionEligibility` 仍为 false，不能自动裁决未知副作用。 |
| 外部适配器 | `BrokerAdapter` 合同、QMT fake、PaperBroker contract fixture/profile 已存在。 | PaperBroker 外部 release 未接入，QMT 没有真实执行 profile。 |
| PostgreSQL | 九表查询模型、权限与 projector 边界已定档；旧 P0 轻量 ledger 可异步投影。 | 九表 migration、正式 projector、RLS/安全视图与生产查询 API 尚未落地。 |

| --- | --- | --- |

## 2. 统一开发与验收规则

### 2.1 功能包必须先完整编码，后统一验收

每个 F 包均遵守以下固定节奏：

```text
F 包设计冻结
  → 完成该 F 包内全部领域合同、实现、迁移、脚本和定向单测
  → 冻结该 F 包的代码候选（不再穿插无关性能改动）
  → 一次性执行该 F 包的静态检查、全量回归、故障演练、集成测试和压测
  → 写入脱敏 evidence manifest 与验收结论
  → 仅通过后进入下一个 F 包
```

- 开发期间允许运行狭窄 unit/contract test 排障；它们只用于定位，不产生“已验收”标记，不替代功能包终验。
- 真实 EMT 委托、499 burst、OMS k6/JMeter 容量测试、Linux 故障演练和恢复演练只能在对应功能包编码完成后集中执行。
- 不得为了单个指标通过而绕开 Journal、callback gap、scope ownership、gate、清理或 `DISARMED` 约束。
- 每次代码或文档变更都必须提交并推送当前分支；功能包验收证据与实现提交必须可相互引用。

### 2.2 每个功能包的统一验收清单

| 验收层 | 强制内容 | 适用说明 |
| --- | --- | --- |
| A1 静态质量 | `ruff check`、默认严格 `pyright`、`git diff --check`、敏感信息扫描 | 默认 Pyright 范围必须为零错误；扩展到旧 P0/工具的类型债务另建治理项，不能伪装为通过。 |
| A2 回归与契约 | 全量 `pytest`、新增合同/JSON schema/兼容性测试、migration/replay fixture | 不把假 Adapter 成功等同于 EMT 结果。 |
| A3 故障与恢复 | 该包涉及的 kill、timeout、tail corruption、容量、callback gap、慢消费者、依赖不可用矩阵 | 每种异常都断言 fail-closed 与可审计证据，而非仅断言进程不崩溃。 |
| A4 性能与容量 | 仅对该包改变的路径执行同口径基线、HDR、CPU/IRQ/迁核/GC 与容量水位采集 | 有真实 EMT 副作用的包使用 Linux 模拟盘；OMS-only 包使用独立负载平台。 |
| A5 部署与可追溯性 | 签名 profile、release manifest、SDK/ABI/hash、配置 hash、证据 manifest、清理核对 | 凭据、订单载荷、账户、价格、地址和密钥不得进入 Git 或公开报告。 |

## 4. 功能包 F1：mmap Journal 恢复、合并与 OMS 事实闭环

### 4.1 编写范围
