# 国金大 QMT 内置 Python 受限后的桥接替代方案

记录日期：2026-10-12（北京时间）。

状态：**方案记录，待券商确认与升级版本能力实测，尚未实施替代桥接。** 本文记录当前环境的选路调整，不宣布新的 IPC 已获支持，不改变现有账户权限或交易门禁。

## 1. 事实来源与决策

用户提供的客户端通知截图标注 2026-10-08，计划于 10 月 23 日完成调整：内置 Python 策略的文件读写、外部网络和数据库连接受到限制，并取消登录页的“独立交易”选项。按本次截图上下文记录计划日期为 **2026-10-23**，实际生效范围与版本仍以国金下发信息为准。

用户进一步确认：当前环境为**国金大 QMT**，MiniQMT 已完全停用，本次讨论对象为大 QMT 内置 Python。客户端精确版本、升级后允许的模块及本机 IPC 能力尚未取得。

据此作出以下方案决策：

1. 撤出此前将 XtQuant/MiniQMT 作为本环境首选替代入口的建议；通用官方文档不能替代当前国金账户的可用权限。
2. 保留 Linux TradeCore、QmtBrokerAdapter、Linux–Windows mTLS 与独立 Windows Edge；重点替换 Edge 与大 QMT 内置策略之间的最后一段桥接。
3. 暂停继续依赖旧读盘 loader 和文件映射 ring 的增量方案投入，保留其代码与历史证据，不在本次记录中删除或切换部署。
4. 优先验证**命名共享内存**及其必要运行能力，验证完成前不启动正式桥接改造。命名管道仅为次级候选，同样需要确认允许范围与实际能力。
5. 若国金不允许任何内置策略与外部进程交互，或升级环境缺少必要能力，则终止该候选路线，申请正式扩展接口或重新评估交易接入渠道。

## 2. 当前工程受影响范围

| 组件 | 当前实现及影响 | 处置 |
| --- | --- | --- |
| Linux OMS/EMS、QmtBrokerAdapter | 不在 QMT 内置 Python 进程中 | 保留；QMT 与 EMT 继续是通用 BrokerAdapter 的同级实现 |
| Linux–Windows 双通道 mTLS | 连接独立 Windows Edge；通知未说明禁止此独立进程联网 | 保留，仍按原证书、ACL 与部署验收门禁运行 |
| Edge SQLite、outbox、幂等与 ACK/cursor | 位于独立 Edge 进程 | 保留；不迁入 QMT 内置策略 |
| QMT 读盘 loader | `qmt_strategy_loader.py` 通过 `open()` 读取 helper，helper 再读取配置和引擎 | 直接涉及文件读取限制，需要替换 |
| QMT Native Engine ring | `_Ring` 先 `open(path, "r+b")`，再基于文件描述符执行 mmap | 当前为文件映射，不能以“共享内存”为由认定不受限制 |

| 现有命名映射探针 | `probe_named_mapping()` 仅验证调用进程可创建并读写映射 | 不构成升级后 QMT 双进程访问、权限、原子性或恢复验收 |

## 3. 候选目标架构

```text
Linux TradeCore / OMS / EMS
          |
   QmtBrokerAdapter
          |
   COMMAND / EVENT mTLS
          |
Windows Edge（独立进程）
  幂等、SQLite、outbox、ACK、恢复证据
          |
  Windows 命名共享内存
  command ring / event ring
          |
大 QMT 内置 Python
  已安装完整策略、官方 timer / callback
          |
      官方交易函数
          |
      国金交易系统
```

这是 QMT 适配层内部的执行桥接替换，不新增 OMS、第二套账户账本或 QMT 到 EMT 的依赖。不引入 MiniQMT 自动回退。

Windows 支持由系统分页文件支撑的命名映射：创建方无需打开普通磁盘文件，另一进程通过对象名称映射同一段共享内存。这只说明操作系统具备该机制，**不说明国金升级后的 QMT 允许调用相关模块或系统 API**。它也不等于“不发生任何磁盘访问”，更不是持久化日志。

## 4. 改造范围与工程约束

### 4.1 策略部署与配置

- 将完整策略通过 QMT 支持的方式直接安装到客户端，取消运行时从外部文件读取 helper、引擎及 JSON 配置。
- 最小引导配置随策略安装；候选初始化协议传递其余必要参数。身份校验依据不能只信任同一份共享内存中的自报字段。
- 精确的策略包版本、scope、generation、ABI 与权限关系必须可核验。私钥和交易凭据不经共享内存交接，也不写入策略源码。
- 新部署方式必须在升级版上验证；不能推定旧 loader 的哈希验证在新方式中自动成立。

### 4.2 命名对象与原子操作

- 为 command/event 分别设计命名映射，保持有界单生产者/单消费者及完整帧提交语义。
- 对象名、访问控制、同账户进程身份和 Windows 会话范围分别设计。名称不可替代身份认证；不默认放宽为 Everyone，也不默认采用跨会话 Global 对象。
- 测试运行身份能否创建/打开指定映射，其他身份能否被拒绝；处理对象抢先创建、旧 generation、尺寸或 ABI 不匹配。
- 先核实升级后可用的原子操作实现。当前自定义 DLL、ctypes 与相关模块均属于待验证依赖；不以普通赋值或 Python GIL 替代跨进程同步。
- 如需调整 ABI，明确升级版本并拒绝旧布局，不能静默将现有文件 ring 当成新映射使用。

### 4.3 QMT 执行上下文

- 在官方允许的 timer/callback 上下文中有界消费和发布消息，不在外部工作线程直接调用交易函数。
- timer 内不能阻塞等待消息；每次处理预算和队列容量必须有界，容量不足时不能静默丢弃命令或交易事实。
- 断连、坏帧、身份冲突和回调丢失触发不可交易状态；恢复需要证据，不因重连成功自动恢复下单权限。
- 不预先承诺新的最小 timer 周期、吞吐或端到端延迟，后续按实际时间点与时钟语义测量。

### 4.4 持久化与恢复

- 共享内存只承担传输；命令状态、幂等记录、event outbox 与 Linux receipt/cursor 继续由既有持久化边界负责。
- Edge 仍须先落盘再发布命令，先持久化回调事实再确认消费。QMT 原生执行与回调落盘之间的缺口不能因更换 IPC 被忽略。
- 映射随相关进程/句柄生命周期可能消失。重建采用新的 generation，保留既有账本，不删除 journal 或换请求 ID 来制造恢复成功。
- 已执行但未获持久化确认的命令按未知执行结果处理，后续通过有完整性证据的查询对账；不可直接重放下单。

## 5. DISARMED 能力探针与推进门禁

第一阶段只做能力判定，不接入原生查询、下单或撤单，不签发交易 capability。使用独立 probe 对象名和测试帧，不复用生产 ring 或订单数据库。

| 阶段 | 实施内容 | 通过条件 |
| --- | --- | --- |
| G0 环境与允许范围 | 取得国金准确客户端版本、升级说明及外部 IPC 允许范围 | 明确命名映射、所需模块/API 与策略安装方式的支持或限制；无法确认则标记待定 |
| G1 策略与基础能力 | 在升级测试版安装完整策略，检查启动、timer、模块和原子调用 | 无外部文件 loader 依赖；必要模块/API 实际可用，受限项明确报错 |
| G2 双向通信 | Edge 与 QMT 打开同一组命名映射，交换固定无业务测试帧 | 双向序号、长度、CRC/哈希、身份与可见性正确；错误身份被拒绝 |
| G3 并发与容量 | 验证原子提交、环回、边界容量、半帧和损坏帧 | 不读半帧、不静默覆盖或丢失；背压和故障状态可观察 |
| G4 生命周期 | 分别停止/重启 QMT 和 Edge，模拟映射消失、旧 generation、句柄清理 | 能识别失联与旧对象；仅按明确的新会话流程恢复探针 |
| G5 改造决策 | 汇总原始证据与支持范围 | G0–G4 均满足才进入正式 ring/配置/执行入口改造；否则保留阻断结论 |

旧客户端结果只能用作对照，不能作为 2026-10-23 升级后兼容证据。若拿不到升级测试版，记录为升级后能力待测，不以旧版本成功替代。

探针验收上限拟定为 `BIGQMT_NAMED_IPC_PROBE_DISARMED`（文档规划标识，尚未实现为运行时状态）。通过也不代表交易 READY、原生 callback 完整性、查询终态、恢复或性能验收通过。

归档至少包括：客户端版本与取得来源、策略/Edge 代码版本和哈希、Python/Windows 版本、实际运行身份与会话、对象 ACL、原子实现、测试序号/校验结果、故障退出原因及两端重启证据。不得归档凭据或原始账户/订单数据。

## 6. 候选失败时的处置

命名管道等其他本机 IPC 不能仅因“不使用 TCP”就认定符合限制；如评估，必须重新核对允许范围与升级环境能力，不作为隐式回退。localhost、Redis、SQLite、普通文件队列也不能解决本通知已经指出的限制。

若券商明确禁止所有内置策略对外交互，或必要系统调用不可用，则请求国金提供正式支持的扩展接口/交易接入方案。其他券商或 EMT 渠道需另核对账户、市场、品种、权限与订单语义，不直接替换当前国金账户。GUI 自动点击不作为当前可靠交易桥接的实现路线。
