# EMT 普通与信用账户发布范围与验收定档

> 状态：**实施中**（2026-09-15）。本文件定义 `emt-ordinary-credit-v1`：普通证券、资金、信用账户能力优先；期权代码保留在完整 SDK catalog 中，但不属于本发布范围，默认不可调用。本文件不改变现有热路径、三 scope/process execution 分片、`fastspi v2` 或 `RECOVERED_DISARMED` 安全结论。

## 1. 发布范围

| 类别 | 本发布处理 | 说明 |
| --- | --- | --- |
| 生命周期 | 启用 | 会话、错误、SDK ABI、连接健康仍是所有账户的共同前提。 |
| 普通证券 | 启用 | 普通报单、撤单、订单/成交/持仓/资产/资金查询。 |
| 资金与账户 | 启用 | `FundTransfer` 及其专属查询、ETF/IPO/证券/港股通参考查询。 |
| 信用账户 | 启用 | 融资买入、融券卖出、还款、卖券还款、展期、额度调拨及全部可调用信用查询。 |
| DMA / 黑白名单 | 启用 | 作为普通账户准入与交易参考查询的一部分。 |
| 期权 | **禁用** | 所有 `option` 域 API/SPI 在模块入口返回 `CAPABILITY_UNAVAILABLE`；不删除 catalog、ABI attestation 或历史证据。 |

`EmtTradingReleaseScopeV1` 是部署范围门禁，不替代账户权限。即使一个 API 位于上述范围内，仍须同时通过 account capability、显式策略权限、approval、Journal-first 事实、lane 与 session ownership 门禁。

## 2. 已实现的范围门禁

`ORDINARY_CREDIT_RELEASE_SCOPE_V1` 的 id 固定为 `emt-ordinary-credit-v1`，仅启用 `lifecycle`、`securities`、`fund`、`credit`、`reference`、`dma` 六个域。

1. `EmtTradingQueryServiceV1` 在调用 SDK 前检查 scope；期权查询不能进入 request-id registry 或 SDK。
2. `EmtControlMutationDispatcherV1` 在写入 `PRE_NATIVE` 前检查 scope；期权控制操作不能留下半条 Journal 事实。
3. `EmtFullTradingModuleV1` 检查 Fast/Control mutation，并要求 Query service、Control dispatcher 与自身使用相同 scope，避免组合时遗漏限制。
4. capability evidence 仍需覆盖完整 `TraderApi`/`TraderSpi` catalog；但 controlled release gate 只计算本 scope 的阻断项。完整 SDK 覆盖布尔值仍保持独立，不能因为禁用了期权就被改写为全 API/SPI 已验证。

## 3. 普通账户验收包 OC-2

新的 Git 生成器 `ordinary_credit_query_fixture_v1.py` 生成目录完整但不含凭据的 fixture：当前启用 **24 个普通账户**、**22 个信用账户**只读候选，期权为 **0**。其中新增的普通账户候选为：

- `QueryPosition`、`QueryOrders`、`QueryTrades`、`QueryAsset`、`QueryFund`；
- `QueryFundTransfer`（`serial_id=0` 的无副作用筛选）；
- `QueryIPOInfoList`、`QueryIPOQuotaInfo`、`QueryIssueInfoList`、`QueryYesterdayAsset`。

下列查询不写入静态 fixture：按 EMT ID 的订单/成交查询只使用本系统当次控制订单在进程内返回的 ID；`QueryOtherServerFund` 需要账户私密字段，只能由服务器忽略配置中的受控 resolver 注入。两者都不得以硬编码账户字段或别的系统订单替代。

验收顺序：先一轮低频 capability probe；仅原生受理且收到正确 request-id 终态 callback 的项目进入三轮低频样本；分页项额外验证第一页、cursor、末页及空结果。每轮结束通过 `QueryUnfinishedOrders` 做只读清理核验，不对共享账户实施泛撤单。

`QueryOrders` 是故意保留的全历史诊断项，不能使用默认 4,096 深度 ring 后把尾部终态丢失误判成柜台无末条。OC-2 fixture 固化 `minimum_callback_capacity.ordinary=8192`；普通账户命令必须显式使用 `--callback-capacity 8192`，否则在创建 EMT session **之前**失败。信用 scope 下限为 4,096，仅作用于隔离的只读验收进程，不会调整 execution hot path 的队列容量。

## 4. 信用账户验收包 OC-3

新增信用只读候选为：`QueryCreditDebtInfoByPage`、`QueryCreditTickerDebtInfo`、`QueryCreditTickerAssignInfo`、`QueryCreditExcessStock`、`QueryMulCreditExcessStock` 与 `QueryCreditPositionExtraInfo`。公共筛选标的仅来自 EMT 示例/既有 T6 公共费率查询；它不代表持仓、券源或下单标的。

信用 mutation 继续严格按单操作、单 lane、每秒最多一条、无自动重试运行：

| 操作 | 当前闭环 | 本轮补强条件 |
| --- | --- | --- |
| 融资买入 / 融券卖出 | 已有本系统 order-id → callback → 精确查询 → 撤单闭环 | 每次先 query 可融资标的/券源，且仅使用不会成交的经批准限价。 |
| `CreditCashRepay` | 已有专用 callback 与 `QueryCreditCashRepayInfo` 对账 | 保持 1 单位、一次运行一个动作或既有受控批次；未知提交只查询、不重试。 |
| `CreditQuotaTransfer` | 已有正反向 1 单位、callback 与 serial 查询闭环 | 保持净变化归零。 |
| `CreditCashRepaySpecifiedDebt` | 驱动及 fail-closed 对账路径已存在 | 仅在发现当前有效债务且 callback 可用时实发；旧债务或无 callback 只记录 blocker，绝不重试。 |
| `CreditSellStockRepayDebtInterestFee` | `CAPABILITY_UNAVAILABLE / unsupported_simulated_venue` | Linux Python binding 具备入口，且实时最小候选预检已通过；但 2026-09-15 单笔 Journal-first compatibility probe 同步返回 `230113`，未产生 native order id 或 callback。保持 fail-closed，等待 EMT 提供支持该业务的环境；正式 adapter 发射器亦不得因该 probe 而标记已验收。 |
| `CreditExtendDebtDate` | Control lane 合同已存在 | 仅由柜台提供当前可展期债务后执行；`230113` 或过期债务不是可接受替代。 |
| `CreditMarginAvlTransfer` | 显式拒绝 | 当前 Linux Python binding 缺少 API/SPI；必须等待 EMT 的可验证 binding。 |

`QueryCreditPositionFullRate` 当前收到 `is_last=false` 后无终态；它保持 `blocked_semantics`。该问题与 Python 实现无关，不能通过本地超时推断完成。取得 EMT 的完成语义、修复柜台回调，或供应商签署等价可验证语义前，普通+信用 scope 也不得宣布全能力 READY。

## 5. 本轮验收与发布判定

代码验收要求：scope 单元测试覆盖普通/信用允许、期权 Query/Fast/Control 均在副作用前拒绝、scope 组合不一致拒绝；fixture 单元测试验证期权零启用且不含敏感字段。

服务器验收要求：仅通过 Git 拉取当前 revision 到正式 acceptance checkout，生成 fixture 后依次运行普通、信用只读 probe；所有真实 mutation 继续使用服务器忽略的 armed fixture。报告只保留 API 名、profile、终态、数值错误码、count、环境 hash 与时间统计，不保留账户、标的、订单、资金、凭据或回调 payload。

发布结论分三层：

1. **scope code ready**：模块入口和 evidence evaluator 的范围隔离已通过本机测试；
2. **scope capability accepted**：本 scope 内每项计划的真实证据、命令闭环和清理均通过；
3. **scope READY**：第 2 层通过，且 EMT 的 `QueryCreditPositionFullRate` 终态、保证金可用划拨 Linux binding、权威恢复证书等外部阻断均已解决。现阶段只能维持 `DISARMED` / `RECOVERED_DISARMED`，不能自动交易。

## 6. 2026-09-14 EMT 模拟盘真实证据

服务器先以 Git revision `0fddcc4` 部署 scope，再以 `6be4c50` Git 快进部署 callback-capacity gate 并复验；SDK、账户配置和 armed mutation fixture 均保留在服务器受控目录，报告未写入账户、标的、订单、资金或 callback payload。

| 验收项 | 真实结果 | 判定 |
| --- | --- | --- |
| OC-2 普通只读复验 | 24 个候选中 22 个完整终态；`QueryOrders` 在 8,192 ring 下获得 5,294 次 callback、5,293 条数据和 `false,true` 终态，ring 峰值 5,280 | 通过；默认 4,096 的测量缺口已关闭 |
| OC-2 外部语义 | `QueryIPOInfoList`、`QueryYesterdayAsset` 在 8 秒内均无 callback | 记录为 EMT/柜台 blocker，不得由本地超时推断成功 |
| OC-3 信用只读复验 | 22 个候选中 19 个完整终态；ring 峰值 99，未发生容量压力 | 部分通过 |
| OC-3 终态语义 | `QueryCreditPositionFullRate` 仅收到 `is_last=false` 后超时 | `blocked_semantics`，保持 fail-closed |
| OC-3 模拟柜台能力 | `QueryCreditExcessStock`、`QueryMulCreditExcessStock` 同步返回 `230113` | 记录为模拟柜台业务不支持，不得改写为 API 已验收 |
| 普通资金划拨闭环 | 30 组正反向；60/60 command outcome 与 60/60 `QueryFundTransfer` serial 对账成功 | 通过，净变化归零 |
| 信用额度调拨闭环 | 30 组正反向；60/60 command outcome 与 60/60 `QueryCreditQuotaTransfer` serial 对账成功 | 通过，净变化归零 |

上述只读容量复验已经关闭普通 `QueryOrders` 的测量缺口；它不会消除 IPO、昨日资产、信用完整费率终态和 Linux `CreditMarginAvlTransfer` binding 等外部 blocker。因此 scope 的最终状态仍为 `DISARMED`，不宣称 `READY`。

## 7. 脱敏 scope 发布证书

`tools/acceptance/ordinary_credit_release_certificate_v1.py` 只读取四份已脱敏的 acceptance report：普通/信用只读报告、普通资金划拨配对报告、信用额度调拨配对报告。它输出 `tradecore.emt.ordinary-credit-release-certificate.v1` 的严格 JSON：仅含输入报告 SHA-256、公开 API 名、终态分类、已验证控制操作、catalog hash 和 blocker；不复制账户、标的、订单、资金、serial、callback payload、地址、凭据或私钥。

证书固定为 `lifecycle=DISARMED`、`release_conclusion=DISARMED_NOT_READY`。`EmtTradingReadinessEvaluatorV1` 会验证其 scope 与 catalog hash，并将证书内 blocker 原样并入 scoped readiness；因此它可使局部实测证据可复核，但绝不能把 22/24、19/22 或两项控制闭环升级成全交易 `READY` 或自动交易授权。

## 8. EMT 查询终态符合性复验（2026-09-15）

本轮以 EMT 官方 2.27 交易 API 为准，而不是沿用旧的 Python wrapper 假设：

- `OnQueryIPOInfoList`、`OnQueryYesterdayAsset` 和 `OnQueryCreditPositionFullRate` 的官方回调签名均为 `(data, error_info, request_id, is_last, session_id)`；`is_last=true` 才表示该 `request_id` 的最后响应。
- 官方接口说明同时确认：`QueryIPOInfoList` 查询当日新股申购信息、`QueryYesterdayAsset` 查询昨日资产；`QueryCreditPositionFullRate` 的市场和证券筛选字段均可省略以查询全部。三项调用返回 `0` 仅表示请求已提交，不是业务结果或终态。
- Linux EMT Python binding `2.27.0.0` 在目标机的 `TraderApi` 自描述签名亦为相同五参数。TradeCore 已取消将 `QueryYesterdayAsset` 当作无 `is_last` 单次回调的旧兼容规则；旧式缺少 `request_id/is_last` 的 callback 只可做受限诊断，不能完成查询。

在 `b3f41be` revision，以单会话、单请求、30 秒等待、普通账户 8,192/信用账户 4,096 native callback ring 执行 payload-free conformance probe。没有委托、撤单、资金或信用 mutation；两次 run 均无 callback gap，ring 最大深度仅为 1。

| 查询 | 原生调用 | 原生 callback 事实 | 验收结论 |
| --- | --- | --- | --- |
| `QueryIPOInfoList` | 返回 `0` | 30 秒内 `0` callback，未到 C5 | `native_accepted_no_callback`，阻断 |
| `QueryYesterdayAsset` | 返回 `0` | 30 秒内 `0` callback，未到 C5 | `native_accepted_no_callback`，阻断 |
| `QueryCreditPositionFullRate` | 返回 `0` | 一次相关 callback，`is_last=false`，随后 30 秒无 `true` | `native_accepted_missing_is_last_true`，阻断 |

这不是 TradeCore 的 parser、ring 或 worker 延迟：前两项没有进入 Python SPI，第三项的 `false` 已被完整解析；三项均无 overflow/gap。也不得把空结果、首条 `false`、本地计时器或重试结果解释为终态。

因此，本 scope 的正确结论仍为 `DISARMED_NOT_READY`。`caf9e2c` 已使用本轮完整 `22/24`、`19/22` 报告及两项 30 组控制闭环生成脱敏证书 `emt-ordinary-credit-6ee821d1f9ffd291e407`（内容 SHA-256：`32e153b9fb0f19b6c84c9371e04462bf2ad361a57c43f4a30c25dd9b3d65cc30`）；证书保留这三项 blocker，不能作为 `READY` 依据。要关闭它们，EMT 仿真柜台或供应商须在相同 SDK version 下做到下列之一：对每个已受理的 request 回调 `is_last=true`（空结果可用空 data/error callback 结尾），或提供版本化、可验证、等价于该终态的完成语义。修复/升级后须固定新的 SDK hash，在同一 probe 连续三轮验证 `request_id` 匹配、至少一个终态 callback、最终 `is_last=true`、零 callback gap；任一轮不满足即继续 fail-closed。

官方依据：[EMT 2.27 callback typedef 与终态说明](https://emt.eastmoneysec.com/api/help/emt__api_8h.html)、[TraderApi 查询参数说明](https://emt.18.cn/docs/EMT_API/classEMT_1_1API_1_1TraderApi.html)。

跨 ordinary/credit、binding 与历史条件型阻断的统一统计见[EMT 模拟盘接口阻断统计](./15-EMT模拟盘接口阻断统计.md)。
