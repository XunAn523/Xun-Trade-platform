# 固定版本消费者黑盒全面压测报告（2026-10-17）

## 1. 结论

当前固定预发布版本在持续混合负载、热态单笔和有界过载安全性上表现稳定，但**不能通过“5,000 笔请求同一时刻释放且全部接纳”门禁**。

- 持续混合负载：三轮均通过 `2,000 SubmitSignal TPS + 5,000 checkpointed event/s + 5,000 Snapshot QPS`，无业务错误、无 trace 丢失、无服务重启。
- 热态单笔：三轮各 10,000 次正式样本全部接纳，P50 为 `0.204 ms` 左右，P95 为 `0.237–0.253 ms`。
- 5,000 同时释放：三轮均为 `4,096 ACCEPTED + 904 ConnectionResetError`，成功率 `81.92%`，未达到 5,000/5,000。
- 8,192 边界突发：三轮均为 `4,096 ACCEPTED + 4,096 ConnectionResetError`；服务保持 active、无 OOM、无重启、trace 零丢失，证明过载是有界且可恢复的，但不代表全接纳通过。
- 失败原因已经由服务端 trace 闭包：`peak_preframe_connections=4096`，恰好等于固定 `preframe_capacity=4096`。这不是 CPU、内存、Journal 或 trace writer 随机抖动。

因此，本版本可继续作为固定容量预发布基线，但若最终门禁要求“消费者 5,000 并发调用全部成功”，下一步必须调整服务端首帧接入容量/接入模型后重新验收。

压测进程仅执行消费者可以执行的公开操作：建立 UDS 连接、编码请求、调用 Consumer V2 接口、读取响应并记录客户端时间戳。它没有 systemd、reset、服务端 trace、Journal 或 Adapter 管理能力。

每轮之前的服务 reset、轮后资源采集与 trace 归档由独立运维编排执行，不计入客户端延时，也不授予压测脚本。

## 7. 当前版本判定与下一门禁

1. 低并发热态：通过。
2. 持续 `2K TPS + 5K events/s + 5K QPS` 混合负载：通过。
3. 有界背压、零 trace 丢失、零 OOM、测试后可恢复：通过。
4. 消费者 5,000 笔同一时刻释放并全部接纳：未通过。

下一次代码优化应只针对 Consumer UDS 首帧接入路径，至少满足：

- 5,000 个已连接消费者共同释放后，`ACCEPTED=5,000`、唯一 LSN=5,000；
- 不以无界扩大队列掩盖问题；仍保留明确的总连接、首帧、ready、输出字节和超时上限；
- 重新执行本报告全部四类场景，证明扩大并发宽度不恶化 HOT-1 与持续混合负载；
- 服务端 trace、cgroup 内存事件、进程重启数与轮后归零必须继续闭包。
