# 实施计划与交付清单

## 1. 实施依赖顺序

```mermaid
flowchart LR
  P0[P0 SDK capability report] --> P1[P1 会话与回调骨架]
  P1 --> P2[P2 Journal 与订单热路径]
  P2 --> P3[P3 事件投递、投影、对账]
  P3 --> P4[P4 压测、故障和安全]
  P4 --> P5[P5 小额实盘灰度]
```

未完成前置阶段不得以 mock 成功替代。特别是 P0 未通过时，只可开发 SDK 无关模块，不可宣称可交易。

## 2. 阶段交付

| 阶段 | 目标 | 主要交付物 | Definition of Done |
| --- | --- | --- | --- |

| P4 | 证明边界 | fake SDK 故障注入、性能工具、基准报告、结构化日志、AlertOutbox、企微通知、告警面板、运维演练。 | 所有 Critical 场景 fail-closed；`WARN+` 可由 `alert_id` 追踪到企微送达/重试；性能与资源基线获批准。 |

## 4. 代码审查阻断项

以下任一项出现即阻断合并：

- callback 中的数据库、网络、文件 I/O、任意等待锁、JSON 编解码或策略业务代码；
- 订单热路径上无基准的同步数据库事务、轮询查询、固定 sleep 或每单新建网络连接；
- `CALL_STARTED`、超时或异常后自动重复 `InsertOrder`；
- 仅通过 symbol、价格或时间推断订单策略归属；
- 无最大容量的队列、无上限的重试、未审计的人工恢复；
- 密钥、账户信息、原生完整订单载荷写入普通应用日志；
- 未同步更新协议、测试和运维文档的持久化/状态机行为变更。
- 没有 `trace_id`/`correlation_id`、可回放审计记录和结构化 `WARN+` 日志的交易、回调或人工状态变更；
- 直接在热路径、SDK callback 或 journal writer 中调用企微 webhook；
- 把企微 webhook、密钥、完整账号或敏感订单载荷写入日志、告警或 trace 属性。

## 5. 每次发布的交付清单

1. 当前环境的 capability report、SDK 校验和、Python/OS/依赖清单。
2. 配置 schema 和脱敏生产配置审阅记录；风险快照规则与版本。
3. 单元、组件、集成、故障、安全和性能报告，以及已知限制。
4. Journal 格式版本、迁移/兼容说明、恢复演练证据。
5. systemd 服务清单、最小权限检查、监听地址和日志保留策略。
6. 回滚计划、当班责任人、风控审批与实盘灰度范围。
7. 审计链完整性报告、关键链路 trace 回放样本、告警/企微送达率与积压报告，以及企微不可用演练记录。
