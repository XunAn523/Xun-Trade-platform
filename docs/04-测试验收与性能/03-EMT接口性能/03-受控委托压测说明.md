# 000010 受控 EMT 委托压测

本压测使用本机忽略文件 `data/performance/fixtures/emt/emt-controlled-order-fixture.json`，覆盖成交卖、成交买、撤单买、撤单卖四个低频场景。每笔 100 股、每个场景最多 10 笔，价格由固定种子在批准范围内选择。

| 场景 | 价格区间 | 证据与收口 |
| --- | --- | --- |
| `fill_sell` | 卖出 1.57--1.59 | `OnTradeEvent`；每笔尝试撤除剩余挂单 |
| `fill_buy` | 买入 1.61--1.63 | `OnTradeEvent`；每笔尝试撤除剩余挂单 |
| `cancel_buy` | 买入 1.57--1.59 | 撤单加 `QueryOrderByEMTID`；发现成交即停止 |
| `cancel_sell` | 卖出 1.61--1.63 | 撤单加 `QueryOrderByEMTID`；发现成交即停止 |

总上限为 40 笔委托、80 次 native 命令、买入名义金额 32,600 元、卖出 2,000 股。命令最小间隔 1 秒，不自动重试；任一失败、回调异常、清理失败或回查失败都会停止，剩余状态以柜台为准人工核验。

## 默认前置门槛与显式绕过

默认情况下，真实 EMT 委托前要求通过账号无关的 1 Hz 本地门槛报告。该报告检查 C0→C1、C1→C2、C2→C3、C3→C4、C5→C6、C6→C7 的 p99 均不超过 1 ms；C4→C5 是 EMT/网络/柜台回调等待，明确排除。

当前本机 30 条验证的 C1→C2（耐久化 `CALL_STARTED`）p99 是 2.344 ms，门槛未通过。这说明本机尚不能宣称本地链路 1 ms p99；它不会被计入真实 EMT 委托的性能验收证据。

若仅需在 EMT 仿真柜台验证报单、撤单、回调及查询接口，可由测试负责人显式绕过该性能门槛。仍必须确认 fixture 为模拟环境并将 `safety.armed` 改为 `true`；绕过只对这一轮受控测试有效，驱动会把 `explicitly_bypassed` 写入报告：

```bash
 .venv/bin/python -m tools.performance.perfbench.cli --driver gateway-controlled-order --sdk-root ./EMT_python_SDK/emt_api_python --accounts-file ./data/performance/config/emt/emt-sim-accounts.json --controlled-order-fixture ./data/performance/fixtures/emt/emt-controlled-order-fixture.json --skip-local-latency-gate --execute-simulated-mutations --output ./artifacts/performance/000010-controlled.json
```

未使用 `--skip-local-latency-gate` 时，驱动仍会校验门槛报告的来源、无账号副作用属性、1 Hz 到达方式及 `passed=true`；缺任一条件均在 SDK 加载、登录、网络连接和委托之前停止。

10 个样本的 p99/p99.9 接近样本最大值，只是观测值而非 SLA；成交和撤单仍取决于当时盘口。该网关未纳入 QuoteApi，不能承诺订单成交或挂单状态。
