# EMT 2.27.0.0 会话重连语义判定

## 1. 结论

TradeCore 当前受控验收环境中实际加载的 EMT Linux Python binding 的运行时版本为
`2.27.0.0`。此版本在一次真实 SDK 连接的受控 TCP RST 后表现为：

```text
初始 OnConnected
  → 仅关闭该 fixture 的 SDK/upstream TCP 对
  → SDK 自行建立新的 TCP 连接
  → 再次 OnConnected
  → 未观察到 OnDisconnected
```

这证明当前环境存在**自动传输重连**，但不能证明 `OnDisconnected` 回调在该类
客户端侧 RST 中可靠交付。经当前定档，该精确样本已成为
`emt_2_27_client_rst_auto_reconnect_v1` 的正式验收标准：满足版本、hash、隔离与传输
事实后，可判定“客户端 RST 自动重连”通过；它不是服务端主动断线、断线风暴或“已恢复并
可继续交易”的证据。

TradeCore 对这个版本的运行时策略是：任何断线、回调缺口、未配对的恢复
`OnConnected` 或进程/SDK 异常都保持交易路由 `DISARMED`；只能在 EMT 权威查询、
双扫描、callback gap 闭合和人工批准完成后恢复。不得在回调中自行调用 `Login()`，
不得因单独收到 `OnConnected` 自动打开新单闸门。

## 2. 版本绑定

以下信息来自 2026-09-14 Linux 隔离验收环境；不包含账户、密码、地址、订单或回调
payload。

| 项目 | 值 |
| --- | --- |
| TradeCore Git revision | `c37f2f1` |
| Python runtime | CPython `3.10.21`（项目 `.venv`） |
| `TraderApi.getApiVersion()` | `2.27.0.0` |
| `libemt_api.so` SHA-256 | `6eb8c354cea94bbde14074b891fe2c5979282fb72ceccf89bfe3f386126dd4c9` |
| `vnemttrader.so` SHA-256 | `d15c6343c45d844992212f987b2d63fd51fb27037991e89086cff367eebce9ee` |
| 测试账户范围 | 普通模拟账户；只建立会话，不执行查询、下单、撤单、资金或信用操作 |

上表的两个二进制 hash 与服务器 `EMT_python_SDK` 隔离目录匹配；任一版本或 hash
变化都必须重新执行本文件第 4 节的能力探测，不能沿用本结论。

## 3. 供应商材料的冲突

SDK 包内有两套不一致的断线模型：

| 来源 | 原文语义 | 对 `2.27.0.0` 的处置 |
| --- | --- | --- |
| `doc/东方财富证券极速交易系统交易API开发手册.html` 的 1.2.4.1、2.2.7 | API 自动重连；通信断开调用 `OnDisconnected`；重连后调用 `OnConnected`。 | 作为现行**规范性契约**，但须以版本化实测确认。 |
| `test/tradertest.py` 与 `doc/EMTTraderApi常见问题.html` 的 Q44–Q45、Q49 | API 不自动重连；在 `OnDisconnected` 中调用 `Login()` 并更新 `session_id`。 | 不能直接应用到本版本；自动重连期间再次 `Login()` 可能制造并发或会话归属歧义。 |

实际测试已观察到自动建立新传输连接和第二个 `OnConnected`，因此“必须在
`OnDisconnected` 中主动 `Login()`”不适用于当前受测行为。另一方面，当前 RST 场景
未收到 `OnDisconnected`，所以手册的完整 callback 序列也尚未得到实证。

## 4. 已执行的可复核探测

工件：服务器 `artifacts/session-semantics/t6-session-semantics-10acf96-r4.json`，
`acceptance_complete=true`。

测试使用独立 EMT native 子进程和 sibling TCP proxy；透明 `connect()` shim 仅影响该
throw-away 子进程中精确匹配的 EMT endpoint。代理对已建立连接发送 TCP RST，并在 12 秒
blackout 内拒绝该 fixture 的重连。它不改防火墙、路由、其他进程或全局网络配置。

| 观察项 | 结果 |
| --- | --- |
| SDK 与 native fastspi 加载 | 通过 |
| 初始 `OnConnected` | 观察到 |
| proxy TCP 对建立 | 观察到 |
| 受控 RST 注入 | 成功 |
| 新 TCP 连接 | 观察到（连接数 1 → 2） |
| 恢复 `OnConnected` | 观察到 |
| 原生 `OnDisconnected` | 未观察到（保留为版本观察值） |
| `reconnect_callback_complete` | `false`（旧的文档 callback 序列字段） |
| `acceptance_complete` | `true`（当前版本化客户端 RST 标准） |

旧的 one-cycle trace `t6-session-fault-a2a62fc-transparent.json` 与本次版本绑定复测一致。
此前也已排除 child report pipe 阻塞、native finalizer abort、Python GIL 与同进程 proxy
互等、初始回调误配对、FIN 弱故障和 loopback endpoint 特殊性。因此该缺口不能归因为
TradeCore 回调处理、代理实现或测量覆盖不足。

## 5. TradeCore 的强制行为

```text
任何可疑会话事实
  ├─ OnDisconnected
  ├─ callback gap / ring overflow
  ├─ SDK 子进程失败、超时或 ABI 漂移
  └─ 运行中出现未配对的 OnConnected
       ↓
关闭新单闸门（fail-closed）
       ↓
保留本地 Journal 与 RouteToken/client_id 归属
       ↓
两次 EMT 权威订单扫描 + callback gap 闭合 + 映射重建
       ↓
RECOVERED_DISARMED
       ↓
人工批准后才可 READY
```

`EmtSession.relogin_after_disconnect()` 是受上层 supervisor 显式调用的生命周期操作；
它不根据任何单一 callback 决定是否重登。该设计同时覆盖旧文档的 manual-login 模型和
当前观察到的自动传输重连模型，而不把二者混用。

## 6. 未覆盖的 EMT 扩展场景

当前版本化客户端 RST 验收不以以下事项为前置；但若后续需要证明服务端主动断线、完整
`OnDisconnected` 时序或断线风暴，EMT 需对以上 API 版本与二进制 hash 书面回答下列问题之一：

1. 提供模拟盘的、按单一 session 隔离的服务端断连/恢复控制入口，并保证能产生
   `OnDisconnected` 与后续 `OnConnected`；或
2. 明确说明在“客户端侧 TCP RST、服务端仍可用”的情况下，不回调
   `OnDisconnected` 是 `2.27.0.0` 的设计语义，并提供替代的、可订阅或可回放的断线/
   恢复完成信号及其时序保证；同时说明是否允许或禁止应用主动 `Login()`。

在收到任一可验证答复前，这些扩展场景保持未覆盖；不得把当前 transport 重连、
`OnConnected` 或本地注入外推为服务端断线证明，更不得把本项通过视为 `READY`。

## 7. 重新验收条件

本标准的每次复验都必须精确匹配第 2 节 API version 与两项 binary hash，并使用隔离
native worker + transparent redirect。报告仅当初始连接、RST 注入、传输重连及恢复
`OnConnected` 齐全时写入 `acceptance_complete=true`。供应商提供扩展 fixture 或版本化等价
语义后，再按该供应商契约独立建立新标准；三轮扩展场景完成后仍须权威查询对账和人工批准，
禁止自动解除闸门。
