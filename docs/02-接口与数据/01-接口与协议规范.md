# 接口与协议规范

> 状态：v0.5 草案。高性能数据面以本规范为准；EMT Python binding 的调用细节仅存在于 `native_api.py`。  
> 传输范围：仅 loopback TCP。跨主机接入须另行完成安全设计和评审。

## 1. 协议原则

1. 使用一条常驻 TCP 连接；握手后每个方向独立递增 `seq`，乱序、重复或超过窗口的帧关闭连接。
2. payload 固定使用 FlatBuffers；字段编号不可复用。控制帧与兼容 WebSocket v1 可用 JSON，但不得进入性能基线。
3. 命令只以 `client_order_id` 或 `client_cancel_id` 幂等；网络 `request_id` 仅用于匹配一次请求/响应。
4. Gateway 可以重复投递事件，客户端必须按 `event_id` 去重并在本地持久化后 ACK。
5. 所有时间字段为 Unix epoch 纳秒 `int64`；网关内部性能判断另用单调时钟，不能把 wall clock 用于超时正确性。
6. 每一条业务命令、原生回报、回调投递、本地状态读取和错误必须带或由 Gateway 补齐 `TraceContext`；没有可关联上下文的消息不得进入交易/投递链路。
7. 本协议是交易信号、账户操作/查询与可靠回调协议，不定义行情消息。全部 EMT 交易/账户 API 以强类型 `operation_kind` / `query_kind` 暴露，不透传原始 C++ 结构体或任意方法名反射。

## 1.1 TraceContext 与审计关联

`HELLO` 完成后，所有 payload 在逻辑上都携带如下不可变上下文。高性能实现可将固定宽度字段放入 FlatBuffers envelope，而非逐层复制 JSON。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `trace_id` | 16 bytes | 一个业务意图的一次端到端链路。客户端可提供；Gateway 验证格式后保留或新建。 |
| `span_id` | 8 bytes | 当前网络/处理阶段的节点 ID。每个 Gateway 边界新建 span 并保留父子关系。 |
| `correlation_id` | UUID/128 bit | 关联人机排障、结构化日志、企微告警和 Ops 查询；Gateway 为缺失值生成。 |
| `command_id` | UUID/128 bit | Gateway 为已接受的订单/撤单生成，贯穿 journal、原生调用与对账。 |
| `event_id` / `delivery_id` | UUID / `u64` | 原生事实与策略投递的稳定去重标识；仅事件方向必填。 |
| `payload_hash` | 32 bytes | 对规范化后的敏感载荷计算哈希；审计与日志使用它而非明文载荷。 |

`trace_id` 不得被用作权限、幂等或订单归属依据；订单幂等只使用 `client_order_id`/`client_cancel_id`。Gateway 必须把 TraceContext、交易日、`session_epoch`、策略 slot、LSN、原生 ID 和每一阶段结果写入 AuditLedger；客户端可通过 `correlation_id` 查询脱敏链路摘要。

## 2. 帧结构

固定头为网络字节序，长度 32 字节。实现必须拒绝未知 magic、错误版本、保留位非零、超过最大帧和无效长度。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `magic` | `u32` | 固定为 `0x454D5447`（`EMTG`）。 |
| `version` | `u16` | 当前 `2`。 |
| `type` | `u16` | 消息类型。 |
| `flags` | `u16` | `ACK_REQUIRED`、`BATCH` 等；其他位必须为 0。 |
| `header_len` | `u16` | 当前固定 `32`。 |
| `payload_len` | `u32` | 不含头的字节数；不得超过配置的 `max_frame_bytes`。 |
| `strategy_slot` | `u32` | 握手后由 Gateway 分配；非握手帧必须匹配连接。 |
| `seq` | `u64` | 单方向严格递增序号；重连后从 1 开始。 |
| `request_id` | `i32` | 与 EMT 原生 `int request_id` 一一关联；查询请求取值为 `1..2_147_483_647`，事件帧为 0。 |

默认 `max_frame_bytes=65_536`。订单帧禁止批量；订单/成交回调帧允许同优先级批量，单帧不得跨越策略或混入本地状态读取结果。

## 3. 消息类型与载荷

| 类型 | 方向 | 必填字段 | 语义 |
| --- | --- | --- | --- |
| `HELLO` | Client → Gateway | `protocol_versions`、`strategy_id`、`token`、`client_nonce` | 建立身份，不接受订单。 |
| `WELCOME` | Gateway → Client | `strategy_slot`、`connection_id`、`server_nonce`、`policy_version`、`session_state` | 验证成功后的连接上下文。 |
| `ORDER_INTENT` | Client → Gateway | `client_order_id`、`symbol`、`market`、`side`、`order_type`、`price`、`quantity` | 请求下单；字段映射先经本地规则，再由 native facade 映射为 EMT 结构体。 |
| `CANCEL_INTENT` | Client → Gateway | `client_cancel_id`、`target_client_order_id` | 请求撤销本网关发出的目标订单。 |
| `ACCOUNT_OPERATION_INTENT` | Client → Gateway | `operation_id`、强类型 `operation_kind`、对应载荷、TraceContext | 资金划拨、信用还款/展期/额度调拨、期权行权/组合等主动 EMT 操作；逐项权限检查。 |
| `ACCOUNT_QUERY_INTENT` | Client → Gateway | `query_id`、强类型 `query_kind`、对应载荷、分页参数、TraceContext | 全部 EMT 账户/交易查询；独立低优先级预算，不占用报撤单/回调资源。 |
| `COMMAND_STATUS_REQUEST` | Client → Gateway | `client_order_id` 或 `command_id` | 仅读取本地 Journal/Event 投影中的已知状态；绝不调用 EMT `Query*`。 |
| `COMMAND_RECEIPT` | Gateway → Client | `command_id`、`client_*_id`、`status`、`journal_lsn` | `ORDER_ACCEPTED` 或明确本地拒绝；不是原生订单状态。 |
| `NATIVE_RECEIPT` | Gateway → Client | `client_order_id`、`order_client_id`、`order_emt_id`、`status` | SDK 非零返回时发送；不等于交易所受理。 |
| `ORDER_EVENT` | Gateway → Client | `event_id`、`order_emt_id`、`order_client_id`、`order_event_seq`、`native_status`、`payload` | 归一化的订单状态事实；同订单序号单调递增。 |
| `TRADE_EVENT` | Gateway → Client | `event_id`、`order_emt_id`、`order_event_seq`、`exec_id`、`payload` | 归一化成交事实；与该订单其他回调共享序列。 |
| `CANCEL_ERROR_EVENT` | Gateway → Client | `event_id`、`order_emt_id`、`order_event_seq`、`error_code`、`error_message` | 原生撤单错误；与目标订单其他回调共享序列。 |
| `SESSION_EVENT` | Gateway → Client | `event_id`、`session_state`、`session_epoch`、`reason` | 登录、断线、重传、对账、`DISARMED`/`READY` 状态变化。 |
| `ACCOUNT_OPERATION_EVENT` | Gateway → Client | `event_id`、`operation_id`、`operation_kind`、原生 ID/serial ID、payload | 资金划拨、信用操作、期权行权/组合等异步结果。 |
| `ACCOUNT_QUERY_ITEM` | Gateway → Client | `query_id`、`query_kind`、`callback_name`、`request_id`、`is_last?`、分页元数据、payload | 一条原生账户/交易查询回调；`is_last` 仅在 EMT 原生签名提供时出现。 |
| `ACCOUNT_QUERY_COMPLETE` | Gateway → Client | `query_id`、`query_kind`、`request_id`、`outcome`、`last_lsn` | 请求完成/失败/超时；不能省略空结果结束事件。 |
| `NATIVE_CALLBACK` | Gateway → Client | `event_id`、`callback_name`、原生关联 ID、请求/分页元数据、脱敏 payload | 全量 `TraderSpi` 回调的版本化副本；受细粒度权限控制。 |
| `COMMAND_STATUS_RESPONSE` | Gateway → Client | `command_id`、`known_state`、`last_event_id`、`last_delivery_id` | 本地持久化状态快照；不能替代可靠回调或原生对账。 |
| `ACK_EVENT` | Client → Gateway | `delivery_id` | 已持久化处理到该投递游标。 |
| `HEARTBEAT` | 双向 | `monotonic_send_ns` | 连接保活和时延观测，不替代 EMT SDK 心跳。 |
| `ERROR` | Gateway → Client | `code`、`retryable`、`message`、`correlation_id`、`alert_id?` | 协议、认证或业务错误；已升级为告警时携带 `alert_id`。 |

## 4. 下单状态契约

```text
RECEIVED
  → REJECTED_LOCAL
  → ORDER_ACCEPTED
      → CALL_STARTED
          → NATIVE_ACCEPTED | LOCAL_SEND_REJECTED | SUBMIT_UNKNOWN
              → [由原生订单/成交回报和对账演进]
```

| 状态 | 对客户端的含义 | 是否可自动重试 |
| --- | --- | --- |
| `REJECTED_LOCAL` | 未调用 EMT，例如权限、参数、额度、幂等冲突或反压拒绝。 | 可以，以同一 ID 在满足修正条件后提交；载荷不可改变。 |
| `ORDER_ACCEPTED` | 命令已进入持久化日志，已获得发射资格。 | 不可作为“可再次下单”的依据。 |
| `CALL_STARTED` | 已开始调用 EMT SDK，副作用是否到达柜台未知。 | 禁止。 |
| `NATIVE_ACCEPTED` | `InsertOrder` 返回非零 `order_emt_id`。 | 禁止。 |
| `LOCAL_SEND_REJECTED` | SDK 明确返回 0 且记录了本地错误。 | 由策略根据错误码决定；应产生新的意图前先确认不属于未知副作用。 |
| `SUBMIT_UNKNOWN` | 异常、超时、崩溃、连接故障等导致无法确定发送结果。 | 禁止；必须经重传流和查询对账。 |

## 5. 错误码

错误码是稳定的网关语义，不透传原始 SDK 文案。原始 `native_code` 和受控脱敏 `native_message` 作为诊断字段附带。

| 代码 | 可重试 | 含义 |
| --- | --- | --- |
| `UNAUTHENTICATED` | 否 | 未完成握手或凭据无效。 |
| `POLICY_STALE` | 是 | 权限/额度快照过期或尚未同步。 |
| `RISK_REJECTED` | 否 | 标的、方向、价格、数量或额度不符合策略规则。 |
| `IDEMPOTENCY_CONFLICT` | 否 | 相同业务 ID 对应不同载荷。 |
| `DUPLICATE_COMMAND` | 否 | 相同业务 ID 已受理；返回既有命令状态。 |
| `BACKPRESSURE` | 是 | 本地有界队列或策略信用不足。 |
| `VENUE_THROTTLED` | 是 | EMT/柜台流控（例如 `211008`）；不得重发已 `CALL_STARTED` 的命令。 |
| `SESSION_UNAVAILABLE` | 是 | 未登录、断线、日切或 `RECONCILE_REQUIRED`。 |
| `CALLBACK_STREAM_BROKEN` | 否 | callback ring 溢出或事件流不可信；等待人工/自动对账。 |
| `UNKNOWN_ORDER` | 否 | 撤单目标没有已证明的原生映射。 |
| `INTERNAL_ERROR` | 否 | 未分类内部错误；携带 `correlation_id`。 |

## 6. 客户端实现要求

- 客户端在发送主动操作前持久化业务 ID 和完整载荷；连接丢失后通过事件重放、`COMMAND_STATUS_REQUEST` 或同一 ID 重交取得既有状态。账户查询使用独立 `ACCOUNT_QUERY_INTENT`，以 `ACCOUNT_QUERY_ITEM/COMPLETE` 异步接收，不能轮询或抢占订单/回调预算。
- 收到 `ORDER_ACCEPTED`、`NATIVE_RECEIPT` 不能更新本地成交或持仓；只有 `ORDER_EVENT`、`TRADE_EVENT` 和后续对账事件可更新事实。
- 对事件按 `event_id` 去重；同一订单按 `order_event_seq` 检查回调缺口，先落地业务处理结果后再发送 `ACK_EVENT`。ACK 可批量且单调递增。
- 接到 `BACKPRESSURE` 或 `VENUE_THROTTLED` 后按 Gateway 提供的 `retry_after_ms` 退避；不得并发制造新业务 ID 绕过限流。
- 未知 `type`、非法长度、未知必填枚举都视为协议不兼容，关闭连接并升级客户端，不允许猜测解析。
- `operation_kind`、`query_kind`、`callback_name` 的完整枚举与权限要求以 [EMT交易与账户接口全覆盖矩阵](./02-EMT交易与账户接口全覆盖矩阵.md) 为准；未知枚举一律拒绝。
